## 作業内容

ブランチ：`feature/v0.2.0`（以下の項目ごとにコミットを分ける）

### 1. 性格を二つの軸に分ける

現在の5種類の性格（強欲・豪胆・正直・慎重・臆病）を廃止し、冒険者ごとに次の二つを持たせる。

| 軸 | 語 | 効く場面 |
|---|---|---|
| 探索 | 大胆／慎重／臆病 | 持ち帰る量、負傷しやすさ、冒険記の文面 |
| 取引 | がめつい／正直／お人好し | 言い値の高さ、値切りの通りやすさ、前金 |

- 画面には主人公が帳面に書き付けた人物評として、`大胆、がめつい` のように二語を読点で並べて表示するだけにする。現在の説明文（`desc`）は表示しない
- 各語の効果はどの場面でも一貫させること（同じ語が場面によって違う意味を持たないようにする）
- 出発点の数値（試算しながら調整してよい）：

| 探索 | 持ち帰り倍率 | 負傷率の加減 |
|---|---|---|
| 大胆 | 1.25 | +0.07 |
| 慎重 | 0.90 | −0.05 |
| 臆病 | 0.75 | −0.09 |

| 取引 | 言い値の割合 | 値切り成功率（基本） | 前金の加減 |
|---|---|---|---|
| がめつい | 0.52 | 0.15 | +10 |
| 正直 | 0.40 | 0.30 | 0 |
| お人好し | 0.46 | 0.70 | −5 |

  意図：正直者は最初から値付けが低く値切る必要がない。お人好しは最初こそ高めに言うが押せば折れる。がめつい者は高く、値切りもほぼ通らない。「相手を見て値切るかどうか決める」判断が生まれるようにする

- 冒険記の性格ごとの一文は探索の軸（大胆・慎重・臆病）に対応させる
- 保存データの `ver` を 2 に上げ、ver 1 のデータを読み込んだときは次のように変換する：強欲→大胆・がめつい、豪胆→大胆・正直、正直→慎重・正直、慎重→慎重・正直、臆病→臆病・お人好し
- 技能を表すタグは別の仕組みとして後の版（v0.4予定）で作る。今回は腕前の表示を残すだけでよい

### 2. 商人の評判を加える

店全体の名声を表す「評判」を新設する。冒険者ごとの「信頼」はこれまで通り残し、両立させる。

- 評判は 0〜100、開始時 50
- 表示は数値ではなく語で示す（例：0〜19 悪名、20〜39 不評、40〜59 無名、60〜79 好評、80〜100 名声）。帳場の上部など目に入りやすい所に置く
- 増減の出発点（試算しながら調整してよい）：
  - 言い値のまま買い取る：+1
  - 値切りに成功：−1
  - 値切りに失敗：−3
  - 買取を断る・返事をせずに一日を締めて破談：−2
- 効果：
  - 値切り成功率に (評判 − 50) ÷ 200 を加える
  - 新しく酒場に来る冒険者の初期の信頼：評判 70 以上なら 4、30 以下なら 2、それ以外は 3
- 目的は「毎回値切るのが最善」という単調な状態を崩すこと。機械的な戦略で数百回遊ばせる試算を行い、少なくとも次を満たすよう数値を調整し、結果を利用者に報告する：
  - 毎回値切る戦略が、言い値で買い続ける戦略より明確に有利にならない
  - 相手の取引の性格を見て値切るかどうか決める戦略が最も勝率が高い（目安 7〜8割）

### 3. 本日の帳簿を折りたためるようにする

- 見出しを押すと開閉する形にする（`details` と `summary` を使ってよい）
- 既定では閉じておき、見出しに件数を表示する（例：`本日の帳簿（4件）`）

### 4. 画面下の切り替えを、台帳の付箋（インデックスシール）に作り直す

- 台帳の下端から付箋が覗いている見た目にし、そこから各画面（帳場・酒場・倉庫と相場・冒険記・設定）へ移る
- 片手で指が届くよう、付箋は画面の下側に置く。iPhoneのホームバーの安全領域に隠れないこと
- 選ばれている付箋は台帳の紙面とつながって見えるようにし、どこを開いているか一目で分かるようにする
- 付箋ごとにわずかに色味を変えるのはよいが、`CLAUDE.md` の配色（羅紗の緑、紙、墨、朱、金）から外れないこと
- 買取の申し出がある間は、帳場の付箋に件数の印を出す（現在の表示を引き継ぐ）

### 5. 売る数を指定できるようにする

- 倉庫と相場の各品に、数を増減する釦（−／＋）と現在の数、「全部」の釦、「売る」の釦を並べる
- 「売る」を押す前に、その数を卸した場合の受取額を、値下がり込みで表示する（例：`4つで 41枚`）
- 釦はiPhoneで押しやすい大きさ（目安 44px 四方以上）にする

### 6. ダブルタップ拡大止めの予備策を、新しい部品に合わせる

v0.1.2で加えた予備策（素早い二度目のタップを打ち消し、釦などなら押し直す仕掛け）は、押し直す対象を `button,label,a,[data-act]` に限っている。

- 本日の帳簿の折りたたみに `summary` を使う場合、素早く二度押しすると二度目が打ち消されて開閉が効かなくなるため、押し直す対象に `summary` を加える
- 付箋や売る数の釦など、今回新しく作る押せる部品がすべて押し直しの対象に入っているか確かめる
- 売る数の −／＋ を素早く連打したとき、押した回数だけ数が変わることを確かめる
